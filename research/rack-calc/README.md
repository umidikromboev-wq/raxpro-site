# Калькулятор КП: раскладка → спецификация → смета

Прототип ядра, из которого собирается коммерческое предложение RaxPro.
Написан на Python как исследование; для сайта портируется в TypeScript
(`lib/rack/`), чтобы один код считал и в браузере, и на сервере.

## Что здесь

| Файл | Что делает |
|---|---|
| `calc_v1_regression.py` | Первая версия + **регрессия по фактическим КП**. Запусти — покажет 7 проверок. |
| `calc_v2_polygon.py` | Контур склада полигоном, колонны и ворота координатами, перебор ориентации, пристенный режим. |
| `blender_scene.py` | Сцена для Blender без интерфейса. Собирает те же 122 секции из тех же чисел. |
| `scene_threejs.js` | Интерактивная модель для страницы КП. |
| `kp-demo.html` | Собранное демо-КП целиком (визуализация, план, 3D, смета). |

## Запуск

```bash
python3 calc_v1_regression.py          # регрессия по реальным КП
python3 calc_v2_polygon.py             # тесты полигона и блокировок

# рендер (Blender не установлен в систему, работает прямо с образа):
hdiutil attach blender.dmg -nobrowse -quiet
/Volumes/Blender/Blender.app/Contents/MacOS/Blender \
  --background --python blender_scene.py -- out.png aisle
hdiutil detach /Volumes/Blender
```

## Формулы: откуда взялись

Восстановлены из фактических КП RaxPro. У «Toshkent.uz» нашлись **и план,
и спецификация** — по чертежу считаются 15 секций в 3 рядах, дальше:

| Позиция | Правило | Расчёт | В КП |
|---|---|---|---|
| Рамы | секции + ряды | 15 + 3 = 18 | 18 |
| Балки | секции × ярусы × 2 | 15 × 2 × 2 = 60 | 60 |
| Замки | балки × 2 | 60 × 2 = 120 | 120 |

Правило замков подтвердилось ещё на «Fathulla» (124 → 248) и «Lion Print»
(534 → 1068), правило анкеров «рама × 4» — на «Sika» и «Fathulla».

**Одно расхождение оставлено намеренно:** у «Toshkent.uz» анкеров 144 при
18 рамах, то есть восемь на раму вместо четырёх. Либо другой тип опорной
плиты, либо ошибка в самом КП. Система должна на таком останавливаться и
спрашивать, а не подгонять молча.

## Статус проверки — что доказано, а что нет

- **Формулы спецификации** (раскладка → рамы, балки, замки, анкеры) —
  проверены точно, 7 из 7 на реальных КП.
- **Алгоритм раскладки** (габариты → расстановка) — проверить пока не на
  чем: ни в одном КП нет пары «точный контур помещения + расстановка».
  Нужны **исходники 3ds Max** хотя бы по двум-трём проектам.

Пристенный режим на приблизительном контуре «Toshkent.uz» даёт 24 секции
по пяти стенам против 15 по трём в фактическом заказе. Расхождение
ожидаемое: контур задан на глаз, и неизвестно, какие участки клиент
сознательно оставил свободными под ворота и приёмку.

## Найденная ошибка, которую поймал тест

Первый вариант перебора выдал на складе 45 × 24 м десять рядов — и это
было неверно: к крайнему ряду не оказалось прохода, паллету туда не
поставить. После добавления проверки доступа получилось девять рядов.

При этом правильный перебор нашёл **на 165 паллето-мест больше**, чем
грубая прямоугольная версия: 1 995 против 1 830 на том же складе.

## Цены в прототипе

Выведены из фактических КП: рама 4000 мм ≈ 1,97 млн сум, 6000 мм ≈ 2,68 млн,
отсюда линейная модель `550 000 + 355 000 × высота_рамы_в_метрах`. Балка 2700
≈ 620 000, замок ≈ 850, анкер ≈ 5 800. **Это оценка для демонстрации,
а не боевой прайс** — его нужно взять у клиента.
